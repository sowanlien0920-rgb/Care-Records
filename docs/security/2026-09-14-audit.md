## 確認したが問題が無かった項目

- **秘密情報**: `.env` / `.env.local` は `.gitignore` 済み（`git check-ignore` で確認）。追跡されているのは `.env.example` のみで、値は空。git 履歴に `.env` / `serviceAccount*` / `.pem` / `.p12` の混入なし。クライアントに出るのは `VITE_FIREBASE_{API_KEY,AUTH_DOMAIN,PROJECT_ID,APP_ID}` / `VITE_BACKEND` / `VITE_USE_EMULATOR` のみで、Firebase の web 設定は公開前提のため誤報告しない。
- **エミュレータ接続の残存**: `src/firebase.ts:94-104` は `BACKEND === 'firestore' && import.meta.env.DEV && VITE_USE_EMULATOR === '1'` の3条件。本番ビルドでは `import.meta.env.DEV` が false になるため到達しない。
- **seed スクリプトの安全弁**: `scripts/seedEmulator.ts:42-65` が `FIRESTORE_EMULATOR_HOST` / `FIREBASE_AUTH_EMULATOR_HOST` を localhost 正規表現で検査し、外れていれば何も書かずに `process.exit(1)`。Admin SDK が Rules を迂回する経路として適切に塞がれている。
- **ルールのデプロイ経路**: `firebase.json` に `firestore` セクションが無く、ルールの実体は `firebase.emulators.json` 側にのみ紐づく。carerecords から `firebase deploy` を打っても nursinglog にルールが配られない。意図的な分離で、理由もファイル冒頭に書かれている。
- **ロールの信頼性**: 権限の源は `users/{uid}`。Rules の `match /users/{uid}` は自己更新を許さず（`uid != request.auth.uid`）、施設アカウントも `supervisor` / `helper` しか発行できない。エミュレータのテスト `自分の role は書き換えられない（昇格の遮断）` が pass。クライアント側も `firestoreAdapter.ts:196-207` で自分の行だけ `users` の値を当て、他人は `canApprove: false` に倒している。**自己昇格の経路は無い。**
- **エラーメッセージによる列挙**: `LoginForm.tsx:60-77` が `user-not-found` と `wrong-password` を同一文言にまとめ、施設コードが対応表に無い場合も同じ文言で返している（`:118-127`）。職員 ID・施設コードの存在判定に使えない。
- **プロファイルキャッシュ**: `firestoreAdapter.ts:92-125` は uid をキーに保持し、`CareStoreProvider.tsx:194-196` の `onAuthStateChanged` で毎回 `clearProfileCache()` を呼んでいる。職員交代で前の施設を掴み続けることはない。
- **他人としてのログイン**: `saveSessionStaffId` が `me.staffId !== staffId` を弾く（`firestoreAdapter.ts:238-241`）。職員切替は表示の切替に閉じている。
- **Web Security**: `dangerouslySetInnerHTML` / `innerHTML` の使用なし。URL パラメータの読み取り・リダイレクトの実装なし。オープンリダイレクトなし（`firebase.json` の `legacy-url` は固定ホストへの 301）。
- **外部 API 連携**: 該当なし。legacy がブラウザから `api.anthropic.com` を直接叩き API キーを localStorage に平文保存していた経路は**移植されていない**（`src/domain/noteBuilder.ts:18-23`）。現状の特記事項生成は純粋関数のみ。
- **依存パッケージ**: `npm audit --omit=dev` で 0 件。
- **ログ出力**: 個人情報を含む `console` 出力なし。`seedEmulator.ts` はエミュレータ専用で、出力はモックの職員名と初期パスワード。

- **Rules 全体**: 既定拒否。`allow ... if true` なし、期限付きテストルールなし、`match /{document=**}` なし。`get` と `list` の分離、`resource` と `request.resource` の使い分けも適切。93件のテストのうち 92 件が pass。
